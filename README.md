# Поиск по нормативным документам вуза — основа RAG

Система поиска ответов по внутренним документам РТУ МИРЭА (положения об аттестации,
отчислении, стипендиях, общежитиях и т.д.) — первый этап RAG-пайплайна: **retrieval**.

Идея проекта: качество RAG почти целиком упирается в поиск. Если нужный фрагмент не найден,
даже самая сильная LLM не сможет ответить и начнёт выдумывать. Поэтому здесь поиск строится и
**измеряется** до того, как подключается генерация.

Документы на русском, формулировки в них канцелярские, а вопросы студенты задают по-человечески —
это и создаёт главную сложность.

## Пайплайн

```
PDF → текст → очистка → нарезка на чанки → индекс (TF-IDF / эмбеддинги) → top-k по запросу
```

- **Нарезка** — по предложениям, с перекрытием в одно предложение (`chunk_sentences`).
  Нарезка по символам (`chunk_text`) оставлена для сравнения: она рвёт слова и теряет контекст.
- **Лексический поиск** — TF-IDF, два варианта: по словам и по символьным n-граммам
  (`analyzer="char_wb"`, 3–5 символов).
- **Семантический поиск** — эмбеддинги `intfloat/multilingual-e5-small` с префиксами
  `passage:` / `query:`, векторы нормированы, близость — косинус.

Модель выбрана под язык данных: популярная `all-MiniLM-L6-v2` обучена на английском и на русских
документах работала бы заметно хуже.

## Оценка

Ручной тестовый набор: **18 вопросов** (`eval_set.py`), минимум по два на каждый из 8 документов,
сформулированных так, как их задал бы студент («академ», «долги», «с платного на бюджет»).

Метрика — **recall@k**: доля вопросов, у которых хотя бы один из k найденных чанков пришёл из
нужного документа.

| Метод | recall@1 | recall@3 | recall@5 |
|-------|:---:|:---:|:---:|
| TF-IDF, слова | 0.500 | 0.778 | 0.944 |
| TF-IDF, символьные n-граммы | 0.611 | 1.000 | 1.000 |
| **Эмбеддинги (multilingual-e5-small)** | **0.778** | 1.000 | 1.000 |

## Выводы

1. **Словарный разрыв — главная проблема лексического поиска.** На вопрос «сколько раз можно
   пересдавать экзамен» TF-IDF поднимал куски, где чаще встречается слово «экзамен», потому что
   в документе пересдача называется «повторной промежуточной аттестацией», а слова «пересдавать»
   там нет вовсе. Эмбеддинги находят нужные фрагменты, потому что сопоставляют смысл, а не слова.

2. **Русская морфология бьёт по TF-IDF по словам:** «экзамен», «экзамена», «экзаменационный» —
   для него разные токены. Символьные n-граммы дешёво это чинят и поднимают recall@1 с 0.500 до 0.611.

3. **Проверка глазами на одном запросе привела к неверному выводу.** По одной выдаче казалось, что
   символьные n-граммы всё портят: правильные чанки ушли из топ-5. Метрика на 18 вопросах показала
   обратное — в среднем этот вариант лучше пословного. Вывод: сравнивать варианты только по метрике
   на наборе вопросов.

4. **Абсолютные значения близости у эмбеддингов неинформативны:** у e5 все скоры лежат в узком
   диапазоне (0.87–0.88), в том числе у нерелевантных фрагментов. Осмысленен только порядок. Это
   придётся учесть при объединении с TF-IDF, у которого скоры на порядок меньше: складывать их
   напрямую нельзя.

## Ограничения (честно)

- Метрика работает на уровне **документа**, а не фрагмента. Документов всего 8, поэтому задача
  относительно простая, и recall@3 упирается в 1.000 — на этом уровне методы уже неразличимы.
  Корректнее размечать правильные **чанки**, это следующий шаг.
- Разметка тестового набора сделана вручную и для нескольких вопросов спорна: ответ встречается
  в двух документах (например, про долги — и в положении об аттестации, и в положении об отчислении).
- Извлечение текста из PDF даёт артефакты: разорванные слова («распрост ранять»), номера страниц
  внутри текста. Часть шума убирается регулярками, часть остаётся.

## Что дальше

- **Гибридный поиск:** объединение лексического и семантического ранжирования (нормализация скоров
  или Reciprocal Rank Fusion), замер прироста по той же метрике.
- **Генерация:** ответ LLM строго по найденным фрагментам, со ссылками на документ, и оценка доли
  ответов, подтверждённых источником.
- **Агент** с инструментами и собственный MCP-сервер.
- **Сервис:** FastAPI + Docker.

## Структура

| Файл | Назначение |
|------|-----------|
| `ingest.py` | загрузка PDF, очистка, две стратегии нарезки на чанки |
| `search.py` | индексы TF-IDF и эмбеддингов, поиск, recall@k, сравнение методов |
| `eval_set.py` | тестовый набор вопросов с указанием документа-источника |

## Запуск

```bash
pip install -r requirements.txt
```

Документы в репозиторий не входят. Скачайте PDF в папку `data/` со страниц
[локальных нормативных актов РТУ МИРЭА](https://www.mirea.ru/about/documents/local-regulations/academic-work/)
и [нормативных документов для студентов](https://student.mirea.ru/regulatory_documents/):
положения о текущем контроле и промежуточной аттестации, о порядке отчисления, об академическом
отпуске, правила перевода и восстановления, положения о стипендиальном обеспечении и о студенческих
общежитиях, правила внутреннего распорядка обучающихся.

```bash
python ingest.py   # проверка: сколько документов и чанков получилось
python search.py   # сравнение методов поиска по recall@k
```

Эмбеддинги кэшируются в `emb_cache.npy`: первый запуск считает их 1–2 минуты, последующие берут из кэша.
